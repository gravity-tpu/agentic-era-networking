# Frontier model selection: why Claude Haiku 5.5

Generated by `scripts/frontier-selection-report.py` from the recorded runs on 2026-10-20 01:05 ET. Every number below is read from a run's `summary.json` or `trials.jsonl`; re-run the script after more runs land. These are zero-shot (Protocol A) results of the abstract evaluation (RQ1 to RQ3): they say nothing about the switch.

## Why this exists

The question for the frontier arm was not "which model is best" but "which is the **cheapest model that can execute the task**": write a rule set for a stated intent that the deterministic verifier admits. Admissible means the verifier accepts it; it does not mean correct on the wire (RQ4) and it is not the cross-intent check.

## How the choice was made

1. **Pilot:** Protocol A, N=3 per intent on all four intents (12 trials per model), 12 candidate models from two providers (Claude Fable 5.1 was probed at N=1 or 2 per intent and not piloted, see below).
2. **Rank:** models with no transport failure and at least 8 of 12 admissible, by **measured** cost per admissible set (not list price).
3. **Stage 2:** N=10 per intent, one candidate at a time, cheapest first, stopping at the first viable one. Viable means at least 90% admissible overall and at least 70% on every intent. More expensive candidates were not run.
4. **Full run:** Protocol A N=50 and Protocol B N=20 on all four intents, on that one model only.

**What was and was not fixed in advance.** The stage-2 thresholds (90% overall, 70% per intent, N=10) were set before any stage-2 result existed. They were set after part of the Gemini pilot table had been seen, and the Claude probes (N=1 or 2 per intent) were run before the Claude pilot, so the pilot cut (8 of 12) and the choice of candidates are **not blind**. The pilot used N=3, which is too small to rank models; its job was to find candidates cheap enough to test properly.

## Why Haiku

Among models that met the pilot cut, Haiku 5.5 had the lowest measured cost per admissible set ($0.0008); the others cost this many times as much per admissible set: gemini-4-argon 10x, claude-sonnet-5-5 11x, gemini-3.8-flash 15x, gemini-3.6-flash 16x, claude-opus-5-5 20x, gemini-3.1-pro-preview 64x. It then cleared the stage-2 rule. The cheaper Google flash-lite models did not meet the pilot cut (they failed INTENT-1 and INTENT-4), so being cheap per trial was not enough: the measure that matters is cost per **admissible** set.

Per intent the doubt is wider than overall, because each intent has a quarter of the trials: at N=50 per intent and 45 successes the 95% interval is 79% to 96%; at N=200 per intent and 180 successes it is 85% to 93%.

## Settings and limits

- **Different settings across arms.** Claude ran at the lowest effort setting; Gemini ran at its default thinking, which uses more tokens, so part of the price gap is the setting and not the model. Gemini ran with temperature 0.2, top-p 0.95 and seeds 1..N; the Claude models accept no seed and Claude Fable 5.1 accepts no temperature or top-p, so the Claude arm used the API's own sampling. The recorded `trials.jsonl` and `summary.json` for every run carry the settings and the prompt hash (the same prompt for every model and provider).
- **Local arm for comparison:** Gemma 4 26B (Mac) ran N=50 per intent; its results are in the parent README. Gemma ran quantized (Q4_K_M per the run notes) where the plan says 8-bit.
- **Selection effect.** Picking the cheapest model that looked good is a winner's-curse set-up: the observed rate of a model chosen because it did well is likely to be a little higher than its true rate. The larger runs exist to measure it without that bias.
- **Admissible is not correct.** This is the verifier's verdict over the modelled fields. The cross-intent check (an INTENT-1-admissible set can still fail INTENT-4) and the on-wire conformance run (RQ4) are separate.
- **Spend.** Recorded spend is the sum of `costMicroUsd` over every frontier run directory; a run that was started and stopped before writing its summary is not in it.
