# Ollama over Tailscale: Qwen2.5 3B (Jetson) and Gemma4 26B (Mac)

Re-run of the earlier sustained test, to validate its report. Raw data is in this directory.

## Setup

- Load generator: `loadgen.py`, run from the Mac over Tailscale. Threads send blocking `/api/generate` requests (`stream: false`, `num_predict: 300`), picking at random from 6 fixed prompts.
- Both models are loaded at once, each with 2 in-flight requests, for 600s.
- Qwen2.5 3B (Q4_K_M): Jetson Orin at `100.118.64.16:11434`.
- Gemma4 26B (Q4_K_M): Mac at `100.112.223.16:11434`.
- Run window: 2026-10-04T00:37:53Z to 00:48:21Z. `run2_results.json` holds the per-request records.

## Results

| | Run 1 (original report) | Run 2 (this re-run) |
| --- | --- | --- |
| **Qwen 3B** requests / errors | 35 / 0 | 37 / 0 |
| Qwen aggregate tok/s | 15.3 | 15.2 |
| Qwen per-request tok/s | 15.4 | 15.4 |
| Qwen latency p50 / p95 | 39.1s / 39.2s | 39.1s / 39.2s |
| **Gemma 26B** requests / errors | 133 / 0 | 131 / 0 |
| Gemma aggregate tok/s | 63.0 | 62.5 |
| Gemma per-request tok/s | 68.4 | 67.8 |
| Gemma latency p50 / p95 | 9.2s / 10.0s | 9.5s / 10.5s |

The first run's figures are within about 1% on throughput and within 0.3s on p50 latency, and neither run had errors. The original report is reproduced.

## Jetson hardware (tegrastats, 5s samples, n=125)

- GPU load (GR3D_FREQ): mean 96.5%, max 99%. The GPU was effectively saturated.
- Board power (VDD_IN): mean 12.5W, peak 13.1W.
- GPU temperature: 42C at start, 56C mean, 59.4C max, with no sign of throttling in throughput.
- RAM: 4.6-5.1 GB of 7.6 GB used. Swap was in use at about 50 MB (it was already at 50 MB at the first sample, before load).

## Caveats

- **Concurrency does not help.** The calibration run showed that both servers handle requests one at a time. Aggregate tok/s stays flat as concurrency rises and latency grows linearly with it. The p50 latencies above are therefore queueing time, roughly twice the single-request time.
- **Gemma loaded size is unexplained.** `run2_mac_ollama_ps.json` reports a loaded size of 2.36 GB for a 25.2B-parameter Q4_K_M model whose weights are 18 GB on disk, with `context_length` 262144. I haven't investigated this, so I can't say why it is so small or what that implies for the Gemma throughput figures.
- **Why Gemma is faster than Qwen is unmeasured.** I did not record Mac GPU, power or memory metrics, so any explanation is a guess.
- **Throughput counts only `eval_count`.** Tokens generated by thinking models are included, but prompt-evaluation time is excluded. Per-request tok/s uses Ollama's `eval_duration`, so it excludes network and queueing time.
- **The tail of the run is cut off.** Requests still in flight at the 600s mark finish after the deadline. Wall time is measured to the last completion, which slightly lowers the aggregate figures.
- **Single run on a single day.** Run 2 is one repeat of the same configuration, not a statistical sample.

## Files

- `loadgen.py`: load generator, used as `python3 loadgen.py SECONDS QWEN_CONC GEMMA_CONC`.
- `run2_results.json`: summary stats plus raw per-request records.
- `run2_tegrastats.log`: Jetson stats.
- `run2_*_ollama_ps.json`: `/api/ps` snapshots taken after the run.
- `run2_start.txt`, `run2_end.txt`: run timestamps.
