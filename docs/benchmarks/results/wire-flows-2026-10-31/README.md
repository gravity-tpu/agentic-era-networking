# Wire flows for the on-wire conformance run: what the testbed can tell apart (Phase 0, 2026-10-31)

Phase 0, step 2 of `docs/research/track-a-closeout-plan.md`. Generated by `scripts/select-wire-flows.ts` (module `src/sdn/wire-flows.ts`, tests `test/invariants/wire-flows.test.ts`) from the recorded evaluation cells; the table and `flows.json` are its output. **Prediction only: nothing here touched the switch.** "Told from the reference" means the verifier's own model predicts a different outcome for at least one chosen flow, so a wire run could see a difference; it is not a measurement of the switch.

## Method

For each of the eight intents: the hand-written reference; its **survivors** (mutants the verifier accepts); and the **recorded sets** (distinct admissible rule sets from every cell under `docs/benchmarks/results/agent-evaluation/`, distinct by behaviour, that is by priority, outputs and match, ignoring rule ids and order). Candidate flows are every IPv4 or ARP frame entering port 1, 2 (and 3 in the last mode) between the addresses the sets mention and the edges of their prefixes. Each candidate is tagged with how the testbed would send it: a real host's own address; an **alias** (an IP alias on a real host, accepted by the owner 2026-10-31); a **forged** frame (a raw frame from a workload NIC; the owner accepted this for workload NICs only); an **injected** frame into port 3 from the O2 capture NIC (not accepted: the capture NICs are receive-only today). A greedy cover picks at most 24 flows that separate the most sets.

## What this says

- **Most survivors cannot be told from the reference by any flow.** With every sendable mode, only 4 to 9 of the 6 to 18 survivors per intent are separable (none for tap-return-isolation, below). The rest behave identically to the reference over the modelled fields (an equivalent mutant, for example a raised priority that changes no outcome): a wire run can show the switch agrees on those, but it cannot discriminate them. This matches the 2026-10-20 run (29 of 38 survivors indistinguishable).
- **Few flows are enough where separation is possible:** 3 to 7 flows per intent separate every separable set (none are needed for tap-return-isolation). The five flows of 2026-10-20 were the right order of size but not the right flows for the four new intents.
- **Aliases matter for three intents** (dns-confinement, dns-quarantine, per-host-allowlist: +1 to +3 survivors told), because they name addresses with no real host. Forged frames add nothing beyond aliases in this universe.
- **Injection into port 3 separates more sets** (for example port1-isolation 36 to 46 of 46 recorded sets, uplink-arp-confinement 42 to 50): the sets differ in how they treat frames from the tap, which the intents leave unconstrained. It needs the O2 capture NIC to transmit, which is a change to the ground-truth arrangement, so it is a new decision for the owner (below).
- **tap-return-isolation has nothing to separate:** its clauses fix every packet class's reachable ports exactly (`mustReach` equals `mayReach` throughout), so every set the verifier accepts behaves identically over the modelled fields, in every mode. A wire run on it checks only that the switch implements the reference (and the model's equivalence), not a difference between sets.
- **The 4,250 figure in the plan counted distinct texts.** By behaviour there are 46, 307, 86, 47, 63, 72, 51 and 78 recorded sets for the eight intents (750 in all), which is the pool the wire run draws from.

## What this does not show

The sender capabilities are declarations from `.agents/network-context.md`, to be validated at the bench in Phase 1 (for example whether the Mac can really send an ARP claim for an alias address, and whether a workload NIC can send the forged frames). Sets that differ only in fields the model does not track (L4 ports, VLAN) are not distinguished here at all. The flow budget (24) and the greedy cover are choices, not optima: ties between equally useful flows are broken by lower mode and then by id, so the chosen set is deterministic but not unique, and a smaller cover may exist.
